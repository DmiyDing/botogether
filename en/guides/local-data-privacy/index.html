Where does Botogether store chats, API keys, and project data?

Updated 2026-11-23

Botogether stores conversations, settings, scoped memories, and file snapshots locally on your computer (under ~/Library/Application Support/Botogether on macOS and your user application-data folder on Windows). Local storage does not mean offline inference: when you run a task, your chosen agent or cloud model provider receives the authorized prompt, project context, and permitted scoped memory.

Steps

  1. Know your local data directory

    On macOS, desktop data lives under ~/Library/Application Support/Botogether. On Windows, it lives in the current user’s application-data location for Botogether. Review any exported files or folders carefully before sharing them.

  2. Distinguish local storage from cloud model processing

    Switching models keeps your saved local Botogether memory intact, while changing which external provider processes subsequent tasks. External memory integrations (if enabled) only receive records permitted for the current task.

  3. Pick the credential storage mode that fits your threat model

    Native CLI sign-ins stay managed by each agent CLI. For custom services in Settings → Models & services, choose between local system-encrypted storage, Mac session-only memory keys, or referencing an existing environment variable name.

  4. Control memory scope and isolated previews

    Use Settings → Memory to keep memories scoped per project or personal use—automatic background extraction is not enabled. On Mac, static HTML layout checks run in an isolated Electron renderer with scripts, network access, and permissions disabled.

Credential storage modes compared

Botogether passes selected custom-service credentials directly to the running task process without rewriting your shell profiles or global agent config files.

ModeWhere the key livesPersistence & trade-offs
Native Agent loginManaged by that Agent CLI (e.g., Claude / Codex login)Follows the upstream tool’s own credential and auth rules.
System-encrypted ciphertextStored encrypted locally (macOS Keychain protects the key)Persists across restarts; macOS may ask Keychain permission. Keys are never copied across modes.
Session-only (Mac preview.4+)App memory onlyCleared on quit, no Botogether Keychain access, no persistent terminal sync; re-enter after restart.
Environment variable referenceStores only the variable name, not the secret valueReads the value from your environment at launch; ideal if you already manage secrets externally.

Update checks and external tools

Official update checks only query the public DmiyDing/botogether release repository and never transmit model credentials, chat messages, or local memories. Keep in mind that third-party agent CLIs and any browser tools those agents invoke remain separate native programs with their own authentication, telemetry, and OS permission behavior.

Good to know

  • Never place API keys, tokens, or private passwords inside bot names, system instructions, chat prompts, filenames, or GitHub Issues.
  • Botogether does not automatically migrate or decrypt keys saved in one storage mode into another mode.
  • Deleting a chat hides it from the sidebar and search; internal tombstones may remain for task consistency, so deletion is not a cryptographic disk wipe.

Questions about this guide

Does Botogether upload my entire project folder to a Botogether cloud?

No. There is no Botogether cloud account or sync server. Your selected agent may send task prompts, project data, and scoped memories to its model provider; third-party tools have their own authentication and telemetry practices. Review their privacy terms and permission prompts.

Are model services in Settings acting as a system-wide network proxy?

No. Saved model services are injected only into the targeted Agent task process—they do not act as a system-wide VPN or proxy, and terminal Claude sync requires separate confirmation while Codex App settings remain untouched.

Do static HTML layout checks open my installed Chrome browser?

No. Since Mac preview.6, static HTML layout verification uses an isolated renderer inside Botogether’s bundled Electron runtime with page scripts, network access, and permission requests disabled.
