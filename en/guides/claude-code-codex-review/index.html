How to make Claude Code and Codex check each other’s work

Updated 2026-11-23

Create two assistants in Botogether—one powered by Claude Code and one by Codex (or Cursor Agent)—put them in a group chat bound to a single shared project folder, and assign explicit @mention roles such as “@Builder make the change, @Reviewer verify edge cases and tests.” Inspect the task details and file diffs before accepting the result.

Steps

  1. Detect or install both agent tools

    Open Settings → Agents to verify that Claude Code and Codex are detected on your computer. On supported systems, Botogether also offers in-app installation buttons for OpenCode, Codex, and Claude Code. You still sign in and manage billing through your own tool accounts.

  2. Create two clear, distinct assistants

    Click + in the sidebar to create one assistant on Claude Code and another on Codex. Give them unmistakable role names like “Builder” and “Reviewer”, choose each assistant’s model, and keep their system instructions focused.

  3. Create a group chat bound to one folder

    Click + again to create a group chat, add both assistants, and bind the exact local project folder they should work on. Every member reads and writes real files inside that selected folder.

  4. Delegate explicitly with @mentions

    Write one clear prompt naming who edits and who verifies, using their exact assistant names. You can ask one to write code and the other to check edge cases, missing tests, or documentation accuracy against real files.

  5. Inspect task details and file diffs before accepting

    Open the task details panel to verify which assistant ran each step and what checks actually executed. Remember that a review only covers what was inspected—open the modified files or diffs before accepting changes.

Ready-to-use @mention prompt templates

When to use a single assistant vs. a two-agent review group

More agents are not automatically better for every prompt. Each assistant turn and review pass uses your configured agent quota or API credits, and running work items currently execute one after another (serially) in the shared project folder.

Task typeRecommended setupWhy
Quick lookup, summary, or draft checklistSingle direct chatLower token cost and faster turnaround when independent verification is unnecessary.
Non-trivial bug fix or refactor2-agent group (Build + Review)A second model family catches blind spots, missing edge cases, and untested assumptions.
Multi-deliverable release prepFocused group (Lead / Dev / QA)Explicit @mentions keep responsibilities separated across real files in one folder.

Verification boundaries to keep in mind

Botogether separates task completion from your manual delivery acceptance. Even when a reviewer assistant reports “looks good”, check the task timeline to confirm which commands or file reads actually happened, approve sensitive tool actions carefully, and review the final diff yourself.

Good to know

  • Either agent can build or review—swap Claude Code, Codex, Cursor Agent, or OpenCode depending on which model is stronger or has available quota.
  • Work items in a group execute serially in the current preview to protect shared project files; adding extra members increases usage cost and coordination time.
  • If a run stops mid-task or its effects are unknown, inspect the workspace files before retrying rather than assuming a blind retry is safe.

Questions about this guide

Do both agents run on separate hidden copies of my project?

In a group chat, assistants share the single project folder you bound to that conversation and execute work items serially. This keeps real files aligned without hidden merge surprises.

Can I mix Claude Code, Codex, Cursor, and free OpenCode models in one group?

Yes. Each assistant keeps its own agent engine, model setting, and instructions, so you can combine tools from different providers in the same project chat.

Does Botogether automatically fix everything if the reviewer finds an issue?

You stay in control. Inspect the review findings and either @mention an assistant to rework the specific issue or fix it manually before accepting the files.
