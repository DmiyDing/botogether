Troubleshooting Botogether: missing agents, timeouts, updates, and safe retries

Updated 2026-11-23

Most setup issues trace back to one of four checks: re-detecting tools and checking login status in Settings → Agents, verifying update availability on official GitHub Releases, inspecting whether a preparation timeout happened before generation started, and confirming an interrupted process stopped before retrying.

Steps

  1. No usable agent? Check Settings → Agents first

    Open Settings → Agents, run re-detection, and inspect any diagnostic reason shown for login or capability checks instead of repeatedly creating duplicate bots. Install and sign in to native CLIs using their official guidance.

  2. Seeing an old interface after updating?

    Quit the running app completely (only after active tasks stop cleanly), install the newer build from DmiyDing/botogether Releases, and launch your standard installed app—do not run a second copy from a build folder. Check Settings → About & updates to confirm the build identity.

  3. Inspect preparation vs. execution timeouts

    Botogether separates protocol initialization, work-session creation, and model-selection timeouts. If a model-selection timeout happens before generation starts, no silent model swap or auto-replay occurs—adjust the model or provider and retry cleanly.

  4. Verify stop status before retrying an interrupted task

    Never assume blind retrying is safe when a task’s effects are unknown. Wait for stop confirmation, inspect the changed files in the project folder, and only click Retry once you know what already ran.

How to file a helpful, safe bug report

When opening an issue on GitHub, include your Botogether version/build identity (from Settings → About & updates), OS and architecture (Apple Silicon Mac or Windows x64), and minimal reproduction steps. Always redact screenshots and never upload your SQLite database, log folder, memory backups, credentials, or private repository files.

Good to know

  • Preview builds check both prereleases and stable releases; stable builds check stable releases only.
  • Retrying a task immediately starts a new run with current bot settings once the prior process is confirmed stopped, which may repeat external side effects if the prior run wrote files or called external commands.
  • A platform installer is only available once its DMG or EXE appears under Assets on a published GitHub Release.

Questions about this guide

Does “cannot check for updates” mean I am already on the latest version?

No. Network blocks, GitHub API rate limits, or missing prereleases can block the check. Always verify against the official DmiyDing/botogether Releases page.

My image preview failed—did Botogether delete the output file?

No. Preview sanitization never deletes the underlying file; use the original download action to inspect the raw bytes safely.

Should I paste my log files or database folder into a GitHub Issue?

Never. Logs, databases, backups, and screenshots may contain project paths, snippets, or credentials. Share only redacted reproduction steps, OS/architecture, and app build identity.
