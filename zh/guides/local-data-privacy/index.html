Botogether 的聊天记录、密钥与项目文件存在哪？本地隐私边界全说明

更新于 2026-11-23

Botogether 把所有对话、配置、分范围记忆和文件快照都保存在你的本机电脑上（Mac 位于 ~/Library/Application Support/Botogether，Windows 位于当前用户的应用数据目录）。但「本地保存」不等于「模型离线运行」：执行任务时，你所选的智能体或云端模型服务会收到本次获准发送的提示词、项目内容和允许范围内的记忆。

操作步骤

  1. 了解本机数据目录位置

    Mac 桌面版数据位于 ~/Library/Application Support/Botogether，Windows 位于当前用户的 Botogether 应用数据路径。向外分享目录或记忆导出文件前，请先检查内容是否含敏感信息。

  2. 分清「本地存储」和「模型云端处理」

    切换模型或引擎时，Botogether 里的本地聊天与记忆记录会完整保留，但后续发送出去的数据处理方会变为新选的服务商。若启用外部记忆引擎，它也只读取当前任务获准使用的记录。

  3. 按需选择合适的 API 密钥保存方式

    原生 CLI 工具的登录仍由工具自身管理。在「设置 → 模型与代理」配置自定义服务时，你可以选择本机系统加密保存、Mac 仅本次打开有效（内存态），或引用已有环境变量名。

  4. 检查记忆范围与独立权限边界

    在「设置 → 记忆」中可手动管理事实偏好与生效范围（目前不提供后台自动提取记忆）。Mac 版的静态 HTML 布局验证使用包内隔离渲染进程，禁用脚本、网络和权限请求。

四种凭据管理方式对比

填入自定义服务密钥时，Botogether 只在任务启动时把选定密钥传给对应 Agent 进程，不改写你的 shell 配置文件，也不改动 Agent 的全局原生配置。

方式密钥存放在哪里特点与安全边界
原生 Agent 登录由对应 Agent 工具自身管理遵循该 CLI 官方的登录态与隐私规则。
系统加密保存本机密文存储（Mac 由钥匙串保护密钥）重启保留，Mac 可能弹出钥匙串授权提示；不跨方式自动迁移旧密钥。
仅本次打开有效（Mac）仅保存在应用内存中退出即清空，不访问钥匙串，不支持终端同步，重启后需重填。
引用环境变量只保存环境变量名称，不保存密钥值启动任务时从系统环境读取，适合已有统一密钥管理习惯的开发者。

更新检查与第三方工具的边界

Botogether 的官方更新检查只请求公开的 DmiyDing/botogether 仓库，绝不携带模型凭据、聊天正文或记忆内容。同时要注意：你选用的第三方 Agent CLI 及其自带浏览器工具属于独立原生程序，它们可能有各自的遥测策略或系统权限弹窗；请分别核对其隐私条款、原生权限设置及授权提示。

注意事项

  • 绝对不要把 API Key、Token 或隐私密码写进助手名称、人设提示词、文件名、记忆条目或公开 GitHub Issues 中。
  • 在设置里配置「模型与代理」并非系统级网络代理或 VPN；同步终端 Claude 配置需要单独确认，Codex App 原生配置不会被修改。
  • 删除聊天会从侧栏和搜索中隐藏该会话，但内部可能保留一致性墓碑标记，并不代表对磁盘扇区做彻底擦除。

本篇常见问题

Botogether 会把我的整个项目仓库上传到官方服务器吗？

不会。Botogether 没有账号体系和云端托管服务，所有历史都留在本机；所选智能体可能将任务提示词、项目数据和范围内记忆发送给对应模型服务；第三方工具也有自己的认证和遥测行为，请核对其隐私条款与权限提示。

使用免费 OpenCode 或自定义模型服务，会被当成系统代理影响其他软件吗？

不会。模型服务配置只在 Botogether 启动该 Agent 任务进程时注入，不会接管系统全局网络流量。

静态网页布局检查会偷偷启动我的 Chrome 浏览器吗？

不会。自 Mac preview.6 起，静态 HTML 布局检查已改为使用应用内置的隔离 Electron 渲染进程，关闭了页面脚本、网络访问和系统权限请求。
