Botogether 常见问题排查：找不到智能体、更新检查失败、超时与安全重试

更新于 2026-11-23

大多数使用卡点都集中在四件事上：先去「设置 → 智能体」看具体诊断原因而非重复建助手；用「无法检查更新」时去官方 Releases 人工核对；区分准备超时与执行中断；对中断状态未知的任务，先检查本地文件再决定是否重试。

操作步骤

  1. 找不到可用智能体？先看诊断原因

    打开「设置 → 智能体」重新检测。若登录或能力校验失败，先点开失败原因按各工具官方指引登录或更新 CLI，不要反复创建新助手。

  2. 更新后界面没变？检查启动入口

    先确认所有任务已正常停止再退出旧应用，从官方 DmiyDing/botogether Releases 安装新版，并从标准应用入口启动（构建目录副本不是第二套安装）。可在「设置 → 关于与更新」核对构建版本。

  3. 分清「准备超时」还是「执行中失败」

    应用区分协议初始化、创建工作会话和选择模型三种超时。若在生成开始前就因选择模型超时而终止，应用不会静默换模型或自动重放请求，换一个可用模型再发即可。

  4. 任务中断时先核对文件，别盲目重试

    只要旧进程停止状态未确认或已产生副作用，千万别假设「点重试一定安全」。先等停止确认、进项目目录检查已有改动，确认无误后再发起重试。

常见现象 → 原因 → 处理速查表

遇到异常时先按下面对照定位，一般无需删除整个数据目录。

去 GitHub 提 Issue 前的三件事

反馈问题时请附上：应用版本与构建身份（设置 → 关于与更新）、操作系统与芯片架构（Apple Silicon Mac 或 Windows x64）、以及精简复现步骤。Issue 全网公开，务必把截图里的个人路径和敏感内容打码，千万不要上传数据库、logs 目录、记忆备份、API 密钥或私有源码文件。

注意事项

  • 预览版构建会检查已发布的预览版与稳定版；稳定版构建只检查稳定版更新。
  • 点「重试」会在确认旧进程已停止后，按原目标与当前助手设置立刻新建一轮任务——如果上一轮已经跑过外部命令或写了文件，重试可能会重复产生这些动作。
  • 只有官方 Releases 页面 Assets 里实际列出的 DMG 或 EXE 才算该平台已提供安装包。

本篇常见问题

提示「无法检查更新」是不是就代表我现在用的是最新版？

不是。网络波动或 GitHub API 限流都会导致检查失败，「无法检查」只表示没查到，请直接核对 GitHub Releases。

图片预览失败了，生成出来的文件是不是丢了？

没有丢。预览失败或被过滤不会删除文件，点击原文件下载仍然可以拿到完整原文件。

提 Bug 的时候可以把本地日志或 SQLite 数据库打包发给你们吗？

不要上传数据库、日志文件夹、备份文件或包含密钥的截图。只提供脱敏后的截图、系统架构、应用版本和复现步骤即可。
