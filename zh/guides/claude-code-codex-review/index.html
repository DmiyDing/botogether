怎么让 Claude Code 和 Codex 互相检查代码？

更新于 2026-11-23

在 Botogether 里分别建一个用 Claude Code 的助手和一个用 Codex（或 Cursor Agent）的助手，把它们拉进同一个群聊并绑定项目目录，然后用真实的助手名字 @ 点名分工（如「@开发 修好某问题，@检查 对照真实文件做复查」）。结束后先看任务详情里的分工记录和文件差异，再决定是否收下。

操作步骤

  1. 先确认两个智能体已经就绪

    打开「设置 → 智能体」，确认电脑上的 Claude Code 和 Codex 已被识别。支持的系统上，应用内也提供 OpenCode、Codex、Claude Code 的一键安装入口；账号登录与额度依然由你自己的工具管理。

  2. 创建两位职责清晰的助手

    点左侧边栏 + 创建助手：一个选 Claude Code，一个选 Codex。起容易区分的名字，比如「开发」和「检查」，各自配置模型和人设提示词。

  3. 建群并绑定同一个项目目录

    再点 + 创建一个群聊，把刚建好的两位助手选进来，并绑定它们要共同操作的本机项目目录。所有成员面对的是同一份真实文件。

  4. 用真实的助手名字 @ 点名分工

    在群里发一条清晰指令，明确谁动手改、谁负责挑错或跑检查。需要调整分工或针对复查意见返工时，继续用真实名称 @ 对应助手。

  5. 核对任务详情与文件证据后再验收

    点开任务详情确认究竟是谁执行了哪一步、实际跑了哪些检查。独立评审只覆盖它实际查过的内容，收下前务必自己看一眼改动 diff 或交付文件。

可直接复制的 @ 分工提示词模板

什么时候值得双智能体互相检查，什么时候单聊更快？

并不是所有任务都要拉群。每次执行、复查和返工都可能消耗对应服务商的额度或费用；而且在当前预览版里，群聊中的工作项在共享目录下是串行推进的，加更多成员不一定更快。

任务场景更合适的用法原因
快速问答、整理清单、查一段代码单个助手私聊响应更快、消耗更低，不需要额外协调开销。
改核心代码、修复杂 Bug、防遗漏2 位助手群聊（开发 + 检查）不同模型家族交叉复查，更容易发现边界盲区与假设错误。
写说明文档 + 核对命令准确性2 位助手群聊（撰稿 + 核验）把“生成”和“逐行核对仓库事实”拆给不同助手，减少幻觉。

把好最后一道人工验收关

Botogether 刻意把「运行结束」与「确认交付」分开。即使检查助手回复“通过”，也建议在任务详情里看看它到底读了哪些文件、有没有执行验证命令；遇到需要授权的命令或写操作，务必在弹窗确认范围后再放行。

注意事项

  • 谁写谁查完全可以互换，Claude Code、Codex、Cursor Agent、OpenCode 都能自由混搭，哪个顺手、哪家额度充足就让谁主力输出。
  • 当前预览版中群里工作项按顺序一个接一个执行，以保护同一目录下的文件不被写花。
  • 若某个步骤中途中断或结果未知，先打开文件夹核对已经改动的内容，再决定是否重新发起，不要盲目点重试。

本篇常见问题

两个助手是在各自隔离的副本里改代码，还是改同一份文件？

目前群聊绑定同一个项目目录并串行执行工作项，两位助手直接看到并操作同一份真实文件，避免合并冲突或不知改到哪份副本。

能把付费的 Claude Code / Codex 和免费的 OpenCode 混在同一个群里吗？

可以。每个助手各自绑定引擎和模型配置，互不干扰，非常适合在群里跨厂商搭配使用。

如果检查助手挑出问题，会自动无限循环改到好为止吗？

不会无限失控循环，决策权在你手上。你可以查看评审详情后用 @ 点名指定助手返工，或自己改完再收下结果。
