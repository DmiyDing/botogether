Mac 或 Windows 打开 Botogether 时提示有风险，怎么办？

更新于 2026-11-23

Botogether 预览版还没做 Apple 公证，也没有 Windows 发布者签名，首次打开时 macOS Gatekeeper 或 Windows SmartScreen 可能提示风险。请只从官方 DmiyDing/botogether Releases 下载，先核对 SHA256 校验值确认文件字节一致，再在系统提供放行按钮时对这一个应用允许打开。

操作步骤

  1. 只从官方 Releases 页面下载

    在官方 GitHub Releases 的 Assets 下获取 Apple 芯片 Mac 版 DMG（或 ZIP）或 Windows x64 版 EXE（或 ZIP）。Source code 压缩包里只有文档，不是安装包。

  2. 打开前先核对 SHA256 校验值

    将下方示例命令中的文件名替换为你下载的安装包路径，算出哈希值后与发布页上对应的 *-SHA256SUMS.txt 逐字比对。注意：校验值一致证明下载字节完整一致，并不等同于官方公证或安全背书。

  3. Mac：在隐私与安全性里允许这一次

    打开 DMG，把 Botogether 拖进「应用程序」并尝试打开一次。如果被拦截，打开「系统设置 → 隐私与安全性」，找到 Botogether 旁的「仍要打开」按钮点击放行。

  4. Windows：通过「更多信息 → 仍要运行」放行

    运行 EXE 安装包。若弹出「Windows 已保护你的电脑」，确认来源为官方 Releases 且 SHA256 一致后，点击「更多信息」→「仍要运行」。

Windows 提示「Windows 已保护你的电脑」SmartScreen 对未签名新应用尚未积累信誉核对官方来源与 SHA256 后，点「更多信息」→「仍要运行」。
提示「已损坏」或报恶意软件警告下载可能残缺、被篡改或触发风险拦截不要强行打开！删除文件，从官方 Releases 重下并重新核对校验值。
被智能应用控制（Smart App Control）或公司策略阻止系统或企业安全策略禁止一切未签名程序保持系统防护开启，勿关闭安全策略；可脱敏后到 GitHub Issues 反馈。

升级版本时的本地安全习惯

Botogether 内的更新检查只访问公开仓库 DmiyDing/botogether，绝不上传模型密钥、聊天正文或记忆内容。手动覆盖安装新版前，先确认旧应用里没有仍在运行或停止状态未知的任务再退出，并保留或备份应用数据目录。

注意事项

  • 不要关掉 Gatekeeper、SmartScreen、智能应用控制或杀毒软件，只对 Botogether 这一个应用单独放行。
  • Intel Mac 新构建当前已暂停，仅保留历史实验性 preview.7；日常请使用 Apple Silicon Mac 或 Windows x64 版本。
  • 只保留一份标准安装入口（Mac 放进「应用程序」），不要把构建目录或临时解压目录当成第二套安装长期使用。

本篇常见问题

为什么现在打开还会有风险提示？

预览阶段尚未完成 Apple Developer ID 公证和 Windows 代码签名，系统会按常规策略对所有未签名桌面应用弹窗提示。请以所下载版本的发布说明为准。

SHA256 对上了就一定代表绝对安全吗？

SHA256 只保证你拿到的文件与官方发布页上的文件一模一样、没有在传输中被篡改或损坏；在软件内部依然要留意权限批准范围与所选云端服务的数据边界。

Mac「隐私与安全性」里没有出现「仍要打开」怎么办？

先从「访达 → 应用程序」里双击尝试打开一次让系统记录拦截，再重新打开「系统设置 → 隐私与安全性」就会看到提示按钮。若电脑受公司策略管控禁止未签名应用，请遵守安全策略勿强行绕过。
